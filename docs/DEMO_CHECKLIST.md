# SignalWatch 演示录屏前人工检查清单

按顺序点击。每一步都应看到右侧「正确结果」。  
正式录屏推荐直接使用公网：https://signalwatch-sfkf.onrender.com  
（本地可选：`npm run build && npm run start` → http://localhost:3000）

详细口播与时间轴见 `docs/VIDEO_SCRIPT.md`。

---

### ① 总览页 `/`

| 操作 | 正确结果 |
|------|----------|
| 打开首页 | 看到品牌 SignalWatch、SIMULATED 徽章 |
| 看四个统计卡片 | 数字来自数据库（初始可为 0） |
| 点「立即调度一轮」 | 无报错；有任务时执行次数可能增加 |

### ② 创建监控 `/create`

| 操作 | 正确结果 |
|------|----------|
| 输入 `贵州茅台跌破1700元提醒我` | 文本框可编辑 |
| 点「解析规则」 | 出现可编辑 JSON；含 `600519`、阈值 `1700` |
| （可选）改冷却为 30 | 输入生效 |
| 点「保存到数据库并启动」 | 跳转到任务详情；状态 ACTIVE |

### ③ 模拟行情 `/market`

| 操作 | 正确结果 |
|------|----------|
| 打开页面 | 表格全部标记 SIMULATED |
| 代码 `600519`，当前模拟价格 `1650`，模拟前收盘价 `1720`，点「覆盖模拟价」 | 提示成功；报价表现价≈1650、前收=1720、来源 SIMULATED |
| （对照）前收改为 `1688` 再覆盖后执行任务 | **不应**因「跌破」触发（前收已在阈值下方，非新跌破） |

### ④ 任务详情（刚创建的任务）

| 操作 | 正确结果 |
|------|----------|
| 确认行情为前收 1720 / 现价 1650 后，点「立即执行」 | 结果 TRIGGERED；出现预警；有解释文案（含前收） |
| 再点「立即执行」 | SKIPPED + 冷却/去重说明 |
| 点「暂停」 | 状态 PAUSED |
| 再点「立即执行」 | SKIPPED，原因暂停 |
| 点「恢复」 | 状态 ACTIVE |
| 把规则阈值改成 `1600`，点「保存并升版」 | 版本变为 v2；版本历史多一条 |
| 打开执行历史 | 能看到以往 TRIGGERED / SKIPPED / 说明 |

### ⑤ 降级与恢复 `/market` → 任务详情

| 操作 | 正确结果 |
|------|----------|
| 点「模拟超时」 | 故障模式=timeout |
| 回任务「立即执行」 | outcome=DEGRADED；任务状态 DEGRADED |
| 点「正常」并「清除覆盖」 | 故障恢复 |
| 再「立即执行」 | 不再降级；状态回到 ACTIVE；未触发时有「未满足」解释 |

### ⑥ 预警中心 `/alerts`

| 操作 | 正确结果 |
|------|----------|
| 打开列表 | 能看到有效预警；勾选抑制后可见冷却/去重记录 |
| 刷新浏览器 | 数据仍在（**本地** SQLite / **公网 Render** PostgreSQL 持久化；勿把线上说成 SQLite） |

### ⑦ 任务列表 `/tasks`

| 操作 | 正确结果 |
|------|----------|
| 查看行内状态/版本/执行次数 | 与详情一致 |
| 点「立即执行」 | 真实调用后端，非仅弹窗 |

## 录屏红线（不要说）

- 不要说「实时行情」
- 不要说「在线大模型正在决策」
- 不要展示与数据库不一致的编造数字
